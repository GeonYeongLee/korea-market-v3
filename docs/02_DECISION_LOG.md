# 📋 [의사결정 기록] Architecture Decision Records (ADR)

## ADR-001: 전략의 3대 모듈화 (Scanner, Entry, Exit) 도입
* **상태**: 승인됨 (Accepted) - 2026-10-30
* **맥락**:
  * v2에서는 전략 하나가 1,500줄 이상의 거대한 모놀리스로 작성되어 청산 규칙 하나를 변경하려 해도 스캐너와 진입 로직 전체를 재검증해야 했음.
* **결정**:
  * 모든 전략을 `IScanner`, `IEntryRule`, `IExitPolicy`의 3대 인터페이스로 분리하고, `CompositeStrategy` 오케스트레이터로 조립한다.
* **결과**:
  * 스캐너 A, 진입 B, 청산 C를 레고 블록처럼 조합 가능.
  * 유닛 테스트가 개별 모듈 단위로 작성 가능해져 코드 안정성 극대화.

## ADR-002: 합성 틱(Synthetic Tick) 대신 비관적 분봉 체결(Pessimistic Bar Execution) 채택
* **상태**: 승인됨 (Accepted) - 2026-10-30
* **맥락**:
  * 1분봉 데이터로 실전 틱 단타를 검증할 때 발생하는 모호봉(Ambiguous Bar) 문제 해결 방안 검토.
  * 거래대금을 $n$등분하여 $O \to L \to H \to C$ 가상 틱을 생성하는 방안은 실제 09:00~09:15의 급격한 거래량 폭발(Lumpy Poisson Burst)을 반영하지 못해 가짜 정밀도(False Precision)를 야기함.
* **결정**:
  * 인위적인 가상 틱 분할을 배제하고, 분봉 백테스트 엔진에 **엄격한 비관적 판정(동일 봉 발생 시 손절 우선 + 진입 시 호가 캡 슬리피지 강제 부과)**을 적용한다.
* **결과**:
  * 백테스트 속도를 수십 배 빠르게 유지하면서도, 실전 체결 결과가 백테스트보다 나쁘게 나오는 과적합을 원천 차단.

## ADR-003: 장애 회고 및 재발 방지 체크리스트 의무화
* **상태**: 승인됨 (Accepted) - 2026-10-30
* **맥락**:
  * AI 어시스턴트 및 개발자가 컨텍스트 전환 시 과거에 겪었던 호가단위 오류, 미래참조 오류 등의 실수를 반복하는 문제가 있었음.
* **결정**:
  * `docs/00_FAILURES_AND_LESSONS.md`를 단일 진실 공급원(SSOT)으로 운영하고, 모든 코드 작성 전 5대 체크리스트 점검을 강제한다.
